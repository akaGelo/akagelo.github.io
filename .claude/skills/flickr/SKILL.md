# Публикация фото на Flickr

Аккаунт: `akagelo` (`flickr.com/photos/akagelo`), заведён в январе 2013, **бесплатный**.
Публикуется ТОЛЬКО английский текст.

## Ограничения бесплатного аккаунта (проверено 2026-08-16)

- **1000 фото** всего — потолок каталога на Flickr;
- не более **50 непубличных** файлов;
- только Safety Level **Safe**, коммерческая активность запрещена;
- **API-ключи бесплатным аккаунтам не выдают** («API key creation is currently disabled for free
  accounts»), поэтому всё делается браузером через Chrome MCP, как в скилле `/pin`. Скриптовый
  путь откроется только с Pro ($11/мес, $82/год) — решение отложено до оценки отдачи.

Настройки аккаунта уже выставлены: новые загрузки **публичные**, лицензия по умолчанию
**Public Domain Dedication (CC0)**, импорт геоданных из EXIF включён, из поиска ничего не скрыто.

## Чем Flickr отличается от Pinterest (важно для текстов)

| | Pinterest | Flickr |
|---|---|---|
| источник просмотров | поиск внутри сервиса | **группы**, теги, Explore |
| ссылка на сайт | поле пина | кликабельная ссылка в описании |
| текст | цепочки поисковых фраз | коротко; ключи живут в **тегах** |
| срок жизни | вечнозелёный | всплеск в первые сутки |

Отсюда: длинные SEO-описания на Flickr не нужны и раздражают сообщество. Ключевые слова
уходят в теги, описание — две-три строки плюс ссылка.

## Процесс (диалоговый цикл, по одному фото)

1. Пользователь даёт slug, либо предложи кандидата из очереди (см. «Очередь»).
2. Посмотри фото (`src/assets/photos/<slug>.jpg`) и YAML (`src/content/photos/<slug>.yaml`).
3. Составь и покажи пользователю **на двух языках** (публикуется EN, RU — для контроля):
   - **Title** — авторское название. То же, что в `title:` YAML (и в `pin.title` до тире), если
     фото уже пиналось: одно фото = одно название во всех каналах. Локацию в title не пихать —
     она уходит в теги и геометку.
   - **Description** — 2–3 строки: что за место/ситуация, без беллетристики (пользователь считает
     её кринжем), затем с новой строки ссылка `https://vyukov.ru/?utm_source=flickr&utm_medium=photo#<slug>`.
   - **Tags** — 10–20 штук, вот где ключи. Смешивать: жанр (`street photography`,
     `candid`, `documentary`), локация (`Moscow`, `Russia`, район), сюжет (`rain`, `alpaca`,
     `night`), техника (`black and white`, `telephoto`), плюс темы из `tags:` YAML.
     Многословные теги Flickr понимает — писать как есть, в нижнем регистре.
4. После «ок» — загрузка субагентом (см. ниже), затем запись состояния и коммит.
5. Авторское название дублируй в `title:` YAML, если оно там ещё пустое.

## Группы

Просмотры на Flickr приходят из групп, а не с профиля. Аккаунт вступает в них **руками
пользователя** — у групп бывают правила и модерация вступления.

Правила, за которыми следить: у большинства лимит 1–2 фото в день, у части действует
«give 2, take 1» (за своё фото прокомментируй два чужих). Нарушение — исключение из группы.

Раскидывать фото по 1–3 группам, самым точным по теме. Список групп аккаунта — в
`groups.md` рядом с этим файлом (обновлять по мере вступления).

## Очередь

Кандидаты: фото без блока `flickr:`. Приоритет — `favorite: true`, `rating: 5`, и уже
пинившиеся кадры (у них есть проверенное название). Темп мягче, чем на Pinterest: Flickr
не наказывает за объём, но лента группы не любит заливки пачкой — 1–3 фото в день.

## Состояние в YAML (`src/content/photos/<slug>.yaml`)

```yaml
title: "Grey Season"              # авторское название → сайт
flickr:
  title: "Grey Season"
  description: "..."              # EN, с ссылкой на сайт
  tags: [street photography, moscow, russia, black and white]
  groups: ["Hardcore Street Photography"]
  url: "https://www.flickr.com/photos/akagelo/<id>/"
  posted: 2026-08-16
```

Схема — в `src/content.config.ts`. После публикации: `npm run build` (санити) → коммит.
Push копится пачкой (как у пинов).

## Загрузка: Sonnet-субагент + Chrome MCP

Публикует НЕ основной агент, а субагент (`model: sonnet`, general-purpose). Браузер один —
субагент только один, не параллелить (и не запускать одновременно с `/pin`).

В промпт субагенту дать: точные тексты, путь к jpg, теги, группы и рецепт ниже.

Рецепт:
1. Инструменты грузить через ToolSearch: `take_snapshot`, `click`, `navigate_page`, `type_text`,
   `upload_file`, `wait_for`, `evaluate_script`, `press_key`
   (`mcp__plugin_chrome-devtools-mcp_chrome-devtools__*`).
2. Пользователь должен быть залогинен (профиль постоянный). Если нет — остановиться и попросить.
3. Загрузка: `https://www.flickr.com/upload` → `upload_file` по uid файлового инпута.
4. В форме загрузки заполнить Title, Description, Tags. Поля React-подобные — вводить кликом
   в поле и `type_text`, значение после ввода сверять посимвольно через `evaluate_script`.
   Теги вводятся по одному с Enter (или запятой) — проверить, что не слиплись.
5. Проверить, что privacy = Public и лицензия = CC0 (должны подтянуться из дефолтов аккаунта).
6. Кнопка «Upload N photos» → подтвердить.
7. **Верификация обязательна**: открыть страницу залитого фото, сверить title/description/теги,
   убедиться, что фото публичное и лицензия CC0.
8. Группы: на странице фото «Add to album/group» → выбрать нужные. Если группа требует
   подтверждения или лимит исчерпан — не насиловать, вернуть это в отчёте.
9. Вернуть URL фото вида `https://www.flickr.com/photos/akagelo/<id>/`.

Снапшоты страниц большие: субагенту — сохранять в файл (`filePath`) и грепать, не читать целиком.

## Грабли

- **Дефолт приватности.** Историческая причина мёртвого аккаунта: в настройках стояло
  «View: Only you», всё залитое было приватным. Исправлено 2026-08-16, но при странностях
  проверять `flickr.com/account/prefs/photoprivacy/`.
- **Порядок тегов не важен, регистр не важен** — Flickr нормализует. А вот пробелы важны:
  `black and white` и `blackandwhite` это разные теги, лучше давать оба.
- **Геометка** подтягивается из EXIF автоматически (включено). У части кадров EXIF без GPS —
  тогда геометки не будет, руками не ставим.
